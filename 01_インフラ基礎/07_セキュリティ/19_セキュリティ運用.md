# セキュリティ運用とインシデント対応

セキュリティ対策は導入して終わりではなく、継続的に監視し、異常を調査し、必要に応じて復旧や改善を行います。この一連の活動をセキュリティ運用と呼びます。

## 運用の主な役割

- **SOC（Security Operations Center）**：セキュリティ上の事象を監視・分析する組織または機能です。
- **MSS（Managed Security Services）**：監視などのセキュリティ運用を外部サービスとして提供します。対象範囲、通知条件、対応責任は契約で確認します。
- **CSIRT（Computer Security Incident Response Team）**：セキュリティインシデントへの対応を調整する組織または機能です。社内外の関係者との連絡や対応方針の調整を担います。

組織の規模や体制によって、これらの機能を同じチームが担う場合もあります。名称だけで役割が決まるわけではないため、検知、判断、封じ込め、復旧の責任分担を定めます。

## インシデント対応の基本

不審な事象を見つけたら、組織の報告手順に従って速やかに連絡します。対応は一般に、次の流れで進めます。

1. 事象を検知し、受付記録を残して担当者へ報告する
2. 影響する利用者、端末、サービス、情報を確認して優先度を判断する
3. 権限と手順に基づいて封じ込め、影響の拡大を抑える
4. 必要な記録を保全し、原因や影響範囲を調査する
5. 安全性を確認してサービスを復旧し、再発防止策を実施する
6. 対応を振り返り、検知方法や手順を改善する

端末の電源を切る、ログを消すなどの操作は、証拠保全や復旧に影響することがあります。独断で実施せず、組織の対応計画と担当者の指示に従います。

実際のインシデント対応では、組織固有の対応計画と役割分担に従います。
