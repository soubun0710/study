# 電子証明書、電子署名、タイムスタンプ

電子証明書は公開鍵と、その鍵の所有者や用途などの情報を結び付け、発行者が署名したデータです。証明書を利用するときは、発行者、用途、期限、失効状態などを検証します。

## 電子証明書

証明書には有効期限があり、期限内であることだけでなく、信頼する認証局から発行されたか、想定する用途に合っているかも確認します。証明書チェーンは、ルート証明書、中間証明書、サーバー証明書などを連ねた構造です。

自己署名証明書は発行者自身が署名した証明書です。自動的に信頼されるわけではありませんが、信頼アンカーとして安全に配布・設定した場合に利用されることがあります。

日本の例として、地方公共団体情報システム機構（J-LIS）のJPKIでは、マイナンバーカードの電子証明書を使ってオンライン本人確認や電子署名を行います。

## 電子署名とタイムスタンプ

電子署名は秘密鍵で作成し、対応する公開鍵で検証します。署名対象データの完全性と署名鍵との対応を確認できますが、それだけで現実の本人性や否認の可能性が常に確定するわけではありません。

タイムスタンプは、第三者の時刻認証局（TSA）が、特定のデータがある時点で存在したことなどを検証できるようにする仕組みです。

## 参考資料

- NIST, *Digital Signature Standard (DSS)*, FIPS 186-5（2023年、連邦情報処理規格）。デジタル署名方式の仕様を定めています。[NIST公式ページ](https://csrc.nist.gov/pubs/fips/186-5/final)
- Internet Engineering Task Force (IETF), RFC 5280, *Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile*（2008年、技術仕様）。X.509証明書と失効リストのプロファイルを定めています。[RFC Editor](https://www.rfc-editor.org/rfc/rfc5280.html)
- IETF, RFC 3161, *Internet X.509 Public Key Infrastructure Time-Stamp Protocol (TSP)*（2001年、技術仕様）。時刻認証プロトコルを定めています。[RFC Editor](https://www.rfc-editor.org/rfc/rfc3161.html)
- 地方公共団体情報システム機構（J-LIS）, 公的個人認証サービス（JPKI）の公式案内。日本における電子証明書の利用例です。[JPKI公式サイト](https://www.jpki.go.jp/)
