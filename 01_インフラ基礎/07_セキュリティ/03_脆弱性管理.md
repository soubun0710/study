# 脆弱性情報の確認と対応

脆弱性情報を受け取ったら、識別番号や深刻度だけで判断せず、自組織のシステムが影響を受けるか、悪用されているか、外部から到達できるかを確認します。脆弱性の技術的な深刻度と、組織が対応する優先度は同じではありません。

## CVEとCVSS

- **CVE（Common Vulnerabilities and Exposures、共通脆弱性識別子）**：公開された脆弱性を識別するための共通IDです。脆弱性を特定する番号であり、深刻度を表すものではありません。
- **CVSS（Common Vulnerability Scoring System、共通脆弱性評価システム）**：脆弱性の技術的な深刻度を評価する共通の指標です。組織固有の影響や対応優先度そのものではありません。
- **NVD**や**JVN**などのデータベースでは、CVEに関する情報や分析を確認できます。

対応優先度を決めるときは、CVSSだけでなく、悪用状況、システムの公開範囲、影響を受ける情報資産、修正による業務影響も考慮します。対応後は、修正が適用されたことと、残るリスクを確認します。

## 参考資料

- CVE Program, CVE Record（脆弱性を識別する共通IDを公開するプログラム）。CVEの目的とレコードを確認できます。[CVE公式サイト](https://www.cve.org/)
- Forum of Incident Response and Security Teams (FIRST), *Common Vulnerability Scoring System v4.0: Specification Document*（2023年、脆弱性深刻度の評価仕様）。CVSSの指標とスコアの意味を確認できます。[FIRST公式仕様](https://www.first.org/cvss/v4.0/specification-document)
- NIST, National Vulnerability Database（NVD）およびJPCERT/CC, Japan Vulnerability Notes（JVN）。脆弱性情報の検索に利用できます。[NVD](https://nvd.nist.gov/) / [JVN](https://jvn.jp/)
- NIST, *Guide to Enterprise Patch Management Planning: Preventive Maintenance for Technology*, NIST SP 800-40 Rev. 4（2022年、技術ガイド）。パッチの特定、優先順位付け、適用、検証を扱います。[NIST公式ページ](https://csrc.nist.gov/pubs/sp/800/40/r4/final)
