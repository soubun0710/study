# 認証の基本

認証は、利用者や端末が「誰であるか」を確認する手続きです。認証しただけでは、対象のシステムで何をしてよいかは決まりません。操作の許可は、別途アクセス制御で決めます。

## 認証の要素と多要素認証

認証要素は、一般に次の三種類に分けられます。

- **知識要素**：パスワード、PINなど
- **所持要素**：スマートフォン、ICカード、セキュリティキーなど
- **生体要素**：指紋、顔など

二要素認証（2FA）は、異なる種類の要素を二つ組み合わせます。ログイン操作を二段階に分けても、同じ種類の要素を続けて使うだけなら二要素認証とは限りません。SMSでコードを受け取る方法は一つの利用例ですが、フィッシング耐性のある認証方式ではありません。

## 主な認証方式

- **HTTP Basic認証**：利用者名とパスワードをBase64で符号化して送る方式です。Base64は暗号化ではないため、使う場合はTLSで通信を保護します。
- **フォーム認証**：Webアプリケーションが入力フォームを通じて利用者を認証する方式です。セッション管理、パスワード保管、CSRF対策なども安全に設計する必要があります。
- **チャレンジレスポンス認証**：サーバーからのチャレンジに対する応答を検証する方式です。独自方式を設計せず、標準化された安全なプロトコルを利用します。
- **クライアント証明書認証**：クライアント証明書と対応する秘密鍵を使って、利用者や端末を認証します。認証後に許可する操作は、別途アクセス制御で決めます。
- **パスキー**：公開鍵暗号を使う認証方式です。秘密鍵は認証器で保護され、端末のPINや生体認証などで利用を承認します。パスキーには端末間で同期できるものもあります。

## パスワードの扱い

サービスごとに異なる十分に長いパスワードを使い、パスワードマネージャーの利用も検討します。パスワードを保管するサービスは、平文や復号可能な暗号文ではなく、適切なソルトと計算コストを使う専用のパスワードハッシュ方式で保存します。漏えいなどの根拠がない定期変更を一律に求めるのではなく、侵害が疑われる場合には変更します。

## 参考資料

- NIST, *Digital Identity Guidelines: Authentication and Authenticator Management*, NIST SP 800-63B-4（2025年、デジタル認証ガイドライン）。パスワード、認証器、多要素認証、フィッシング耐性などを扱います。[NIST公式ページ](https://pages.nist.gov/800-63-4/sp800-63b.html)
- World Wide Web Consortium (W3C), *Web Authentication: An API for accessing Public Key Credentials*（WebAuthn技術仕様）。公開鍵認証を用いるWeb認証の仕組みを定めています。[W3C仕様](https://www.w3.org/TR/webauthn-3/)
- Internet Engineering Task Force (IETF), RFC 7617, *The 'Basic' HTTP Authentication Scheme*（2015年、HTTP認証方式の技術仕様）。Basic認証がBase64符号化を用いる点を定めています。[RFC Editor](https://www.rfc-editor.org/rfc/rfc7617.html)
