# ソフトウェア開発におけるセキュリティ

アプリケーションの安全性は、ネットワークやサーバーの防御だけでは確保できません。設計から開発、依存ソフトウェアの利用、リリースまで、各段階でセキュリティを考慮します。

- **セキュア設計**：想定する脅威や信頼境界を整理し、認証、認可、データ保護を設計する
- **入力と出力の扱い**：入力値を適切に検証し、SQLにはプレースホルダーを使う。画面出力は文脈に応じてエスケープする
- **依存ソフトウェアの管理**：利用するライブラリやツールを把握し、脆弱性や改ざんの情報を確認する。ソフトウェア部品表（SBOM）は構成要素を把握する方法の一つ
- **秘密情報の保護**：パスワードやAPIキーをソースコードやログに含めず、適切に管理する
- **例外とログ**：利用者に内部情報を露出せず、調査に必要な記録は秘密情報を含めない形で残す

チェックリストだけで個別システムの安全性が保証されるわけではありません。テスト、依存関係管理、リリース手順など、具体的な工程は開発体制に合わせて決めます。

## 参考資料

- NIST, *Secure Software Development Framework (SSDF) Version 1.1: Recommendations for Mitigating the Risk of Software Vulnerabilities*, NIST SP 800-218（2022年、セキュアソフトウェア開発の技術ガイド）。開発ライフサイクルにセキュリティを組み込む考え方を参照しています。[NIST公式ページ](https://csrc.nist.gov/pubs/sp/800/218/final)
- Open Worldwide Application Security Project (OWASP), *OWASP Top 10:2025*（2025年、Webアプリケーションの主要リスクを整理したプロジェクト資料）。開発で考慮する代表的なWebリスクの参照先です。[OWASP公式ページ](https://top10.owasp.org/2025/)
