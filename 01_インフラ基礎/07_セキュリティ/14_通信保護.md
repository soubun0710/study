# 通信を保護するプロトコル

通信の暗号化や相手の認証には、用途に応じたプロトコルを使います。暗号化だけで安全性が決まるわけではないため、方式、設定、鍵や証明書の管理も確認します。

## TLSとVPN

TLSは通信内容の機密性や完全性などを保護します。HTTPSはHTTPをTLSで保護します。SSLおよびTLS 1.0、1.1は現行の推奨プロトコルとして扱わず、組織の基準とIETFの推奨に従います。

IPsecはIP層で通信の保護や相手の認証などを行うプロトコル群で、VPNに利用されます。選択する構成によって提供する機能は異なります。

PPTPなどの旧来方式は新規設計で安易に選択せず、現行のセキュリティ基準を確認します。L2TP単体には通信を暗号化する機能がなく、歴史的にはIPsecと組み合わせる構成が利用されました。

## メール、リモート接続、ファイル転送

- **OpenPGP**：公開鍵を使ってメールやファイルを暗号化・署名する方式
- **S/MIME**：証明書を利用してメールを暗号化・署名する方式
- **SSH**：リモート接続を保護するプロトコル
- **SFTP**：SSHを利用するファイル転送方式
- **FTPS**：TLSでFTP通信を保護する方式

## 参考資料

- Internet Engineering Task Force (IETF), RFC 9325, *Recommendations for Secure Use of Transport Layer Security (TLS) and Datagram Transport Layer Security (DTLS)*（2022年、Best Current Practice）。TLS/DTLSの安全な利用に関する推奨です。[RFC Editor](https://www.rfc-editor.org/rfc/rfc9325.html)
- IETF, RFC 4301, *Security Architecture for the Internet Protocol*（2005年、IPsecの技術仕様）。IPsecの構成と機能を定めています。[RFC Editor](https://www.rfc-editor.org/rfc/rfc4301.html)
- IETF, RFC 2637, *Point-to-Point Tunneling Protocol (PPTP)*（1999年、PPTPの技術仕様）および RFC 2661, *Layer Two Tunneling Protocol "L2TP"*（1999年、L2TPの技術仕様）。旧来のトンネリング方式の仕様を確認できます。[RFC 2637](https://www.rfc-editor.org/rfc/rfc2637.html) / [RFC 2661](https://www.rfc-editor.org/rfc/rfc2661.html)
- IETF, RFC 4251, *The Secure Shell (SSH) Protocol Architecture*（2006年、SSHの技術仕様）。SSHプロトコルの構成を定めています。[RFC Editor](https://www.rfc-editor.org/rfc/rfc4251.html)
- IETF, RFC 8551, *S/MIME 4.0 Message Specification*（2019年、メール署名・暗号化の技術仕様）および RFC 9580, *OpenPGP*（2024年、技術仕様）。[RFC 8551](https://www.rfc-editor.org/rfc/rfc8551.html) / [RFC 9580](https://www.rfc-editor.org/rfc/rfc9580.html)
- IETF, RFC 4217, *Securing FTP with TLS*（2005年、FTPSの技術仕様）。[RFC Editor](https://www.rfc-editor.org/rfc/rfc4217.html)
- IETF, RFC 8446, *The Transport Layer Security (TLS) Protocol Version 1.3*（2018年、TLS仕様）。[RFC Editor](https://www.rfc-editor.org/rfc/rfc8446.html)
